# Как добавлять новые места из чата «Места Москва»

Источник мест — групповой чат «Места Москва» в Instagram: туда пересылают рилсы и посты.
Сайт приложения — корень этого репозитория, его раздаёт GitHub Pages
(`https://davidvitkin2005-del.github.io/havchik/`), а бот @Havchik_MSK_bot открывает этот адрес
кнопкой «Открыть». Поэтому обновить приложение = обновить данные, пересобрать `index.html` и запушить в `main`.
Бота трогать не нужно. Токен бота никогда не сохраняй в репозиторий.

Все команды ниже запускаются из корня клона репозитория.

## 1. Новые рилсы в чате

Instagram читается только через Chrome пользователя (Claude in Chrome), где выполнен вход.

1. Загрузи инструменты Chrome одним вызовом ToolSearch, вызови `tabs_context_mcp` с `createIfEmpty: true`,
   открой новую вкладку `https://www.instagram.com/direct/inbox/`.
   Если там страница входа, проверка или капча: ничего не вводи и не проходи, закрой вкладку и сообщи
   пользователю, что нужно войти в Instagram в Chrome. На этом всё.
2. `python3 -I source/tools/snippet.py ig` печатает скрипт. Выполни его целиком через `javascript_tool`
   во вкладке Instagram, затем прочитай результат через `get_page_text`.
   Первая строка: `ВСЕГО В ЧАТЕ N, НОВЫХ K`. Если `НОВЫХ 0`, закрой вкладку и закончи без коммита и без уведомления.
3. Для каждого нового `CODE` реши, что это:
   - **Место, где можно поесть или выпить в Москве** (ресторан, кафе, стритфуд, бар с кухней, пекарня, кофейня) — добавляем.
     В одном рилсе может быть несколько мест (подборки, карусели): добавь каждое названное.
   - **Пропускаем**: не про еду (бани, бильярд, кино, вечеринки, заброшки, рецепты), не Москва,
     подборки без названий мест, доставка без заведения, место закрыто.
   - Название и адрес ищи в подписи (часто после 📍), в соавторах (часто это аккаунт заведения), в отметках и геометке.
     Если не понятно, посмотри комментарии: `python3 -I source/tools/snippet.py comments КОД` → `javascript_tool` → `get_page_text`.
     Не понятно и после этого — пропусти с причиной «место не названо».
   - Место уже есть в `source/data/curated.json` — просто добавь код в его `reels`.
   - `TEXT text:…` — обычное сообщение. Если в нём назван конкретный ресторан, обработай как рилс, иначе пропусти.

## 2. Яндекс Карты

1. Открой вкладку `https://yandex.ru/maps/213/moscow/`.
2. `python3 -I source/tools/snippet.py ya "ключ=Название адрес" "ключ2=…"` → выполни через `javascript_tool` →
   прочитай `get_page_text`. Ключ — короткий латинский идентификатор, которого ещё нет в `curated.json`.
3. Выбери кандидата: адрес совпадает с рилсом, статус `open`. Ссылки на соцсети часто совпадают с аккаунтом из рилса.
   Сеть с несколькими адресами — бери точку из рилса, а если адреса нет, самую центральную.
   Если видишь капчу, не проходи её: сообщи пользователю.
4. Допиши в `source/data/yandex_ids.json`: `"ключ": ["id", "seoname"]` и скачай карточку:
   `python3 -I source/tools/yafetch.py source/data/yandex_ids.json source/data/yandex_raw.json`
   (качает только новые). Если у места статус не `open` или нет часов работы — пропусти с причиной.
   Часы у Яндекса начинаются с воскресенья, `make_places.py` сам переводит их на понедельник.

## 3. Фото

`python3 -I source/tools/contact_sheet.py ключ` печатает путь к листу с превью — открой его через Read.
Запиши 5–6 лучших номеров в `source/data/photo_picks.json`: `"ключ": [3, 0, 5, 1, 2]`.
Сначала еда и зал; не бери меню, QR-коды, листовки, логотипы и портреты людей.
Логотип для метки на карте подтянется сам из карточки Яндекса.

## 4. Описание места

Добавь запись в `source/data/curated.json`:

```json
"ключ": {
  "cuisine": ["Шаурма и кебаб"],
  "type": "Кебабная",
  "tags": ["мангал при тебе"],
  "short": "Кебабы из свежего мяса с мангала у «Марьиной Рощи»",
  "description": "Две-три фразы своими словами: что это за место, чем выделяется, что советуют попробовать.",
  "perks": ["Мясо жарят при тебе", "Без майонезных соусов"],
  "reels": ["КОД_РИЛСА"]
}
```

- Пиши своими словами, не копируй подписи из рилсов. Факты бери из подписи и карточки Яндекса.
- `short` до 70 знаков: показывается в карточке списка. `tags` — 1–2 коротких ярлыка для карточки.
- `perks` — 2–3 фишки. Акции и цены из рилса помечай: «(так было в рилсе, лучше уточнить)».
- `cuisine` — 1–2 значения из уже используемых: Европейская, Шаурма и кебаб, Кавказ и Восток, Бары,
  Завтраки, Рыба и морепродукты, Русская кухня, Бургеры, Мясо и гриль, Стритфуд, Латинская Америка,
  Кофе и десерты, Азия, Пицца. Новое значение заводи, только если ни одно не подходит.
- `type` — коротко, как на вывеске: Ресторан, Кафе, Бистро, Бар, Шаурмичная, Бургерная, Пиццерия, Кофейня…
- Если название из Яндекса неудачное (латиница вместо привычного написания и т. п.), добавь поле `"name"`.

## 5. Отметить разобранное

В `source/data/seen_reels.json` в `reels` добавь каждый новый код:
`"КОД": {"places": ["ключ"]}` или `"КОД": {"skip": "причина"}`. Для текстовых сообщений ключ — `text:…` из вывода.
Обнови `checked_at` (дата по Москве).

## 6. Сборка, проверка, публикация

```
python3 -I source/tools/make_places.py      # в конце не должно быть «!» по новым ключам
python3 -I source/tools/build.py            # пишет index.html в корень репозитория
node source/tests/time.test.js
python3 source/tests/map_check.py /tmp/map  # необязательно: карта, метки, карточка места
```

Закоммить в `main` (в сообщении — какие места добавлены) и запушь. Через минуту GitHub Pages обновит сайт,
и в боте сразу будут новые места. Закрой вкладки, которые открывал.

## 7. Уведомление

Одно короткое сообщение пользователю: какие места добавлены, и одной строкой — что пропущено и почему.
Если новых мест нет, ничего не отправляй.
